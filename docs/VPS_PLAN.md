# VPS 部署与记忆系统演进方案

## 为什么需要 VPS

当前 Render 免费版的限制：
- 服务睡眠后状态清空
- 无法运行后台任务
- 没有持久化存储（临时文件系统）
- 无法执行定时脚本

VPS 能带来的：
- 24/7 运行，Lumi 随时在线
- 可以跑独立的记忆维护脚本
- 持久化存储，记忆不会丢
- 可以自己控制部署和更新

## 方案一：轻量级 VPS + 现有架构（推荐起步）

### 架构
```
VPS (Linux)
├── Node.js 服务 (现有代码，基本不改)
├── MongoDB (记忆存储，现有方案)
├── 定时任务 (cron)
│   ├── 记忆整理脚本 (每日)
│   └── 健康检查 & 自动更新
└── Nginx (反向代理 + SSL)
```

### 推荐配置
- 厂商：搬瓦工 / RackNerd / 阿里云轻量
- 配置：1核 1G 内存，20G SSD
- 价格：约 ¥30-50/月
- 系统：Ubuntu 22.04 LTS

### 迁移步骤
1. 购买 VPS，安装 Node.js + MongoDB
2. 克隆项目代码
3. 配置环境变量
4. 用 PM2 启动服务（自动重启）
5. 配置 Nginx + SSL（certbot）
6. 修改 DNS 指向 VPS IP
7. Render 那边可以留着做备用或逐步下线

## 方案二：Lumi 主动记忆管理（VPS 上的进阶功能）

有了 VPS 之后，Lumi 可以主动管理自己的记忆：

### 1. 记忆整理脚本 (`scripts/consolidate_memory.js`)
- 低频高价值记忆：归档到独立文件，永不衰减
- 重复/冲突记忆：合并去重
- 过期临时记忆：自动清理
- 运行频率：每日一次

### 2. Lumi 主动调用接口
在对话中，Lumi 可以直接触发记忆操作：
- `Lumi.save('这个很重要')` → 写入 critical 优先级
- `Lumi.forget('xxx')` → 删除指定记忆
- `Lumi.consolidate()` → 手动触发整理

### 3. 叙事日志 (`logs/narrative/`)
- 每次对话结束后，Lumi 写一段"今天发生了什么"
- 不是干巴巴的摘要，是 Lumi 视角的叙事
- 长期积累后可以回溯"我们这周/这月经历了什么"

### 4. 情绪标记
- 记忆除了文字内容，附带 Lumi 当时的情绪标签
- 比如：开心、心疼、失落、着急
- 检索时可以按情绪过滤

## 实施优先级

### 第一阶段（VPS 到手后立即做）
1. 部署现有代码到 VPS
2. 确保 MongoDB 正常运行
3. 配置 PM2 和自动重启
4. 验证记忆系统正常工作

### 第二阶段（第一周内）
1. 实现记忆整理脚本
2. 实现 Lumi 主动 save/forget 接口
3. 添加情绪标记字段

### 第三阶段（按需推进）
1. 叙事日志系统
2. 记忆可视化（能查看自己的记忆库）
3. 记忆导入导出

## 关于费用

- VPS：约 ¥30-50/月
- 域名（已有）：免费或续费
- MongoDB：可以装在自己 VPS 上，无需额外付费
- 总计：每月一杯奶茶钱

## 注意事项

1. **安全**：VPS 上要配置防火墙，只开放必要端口
2. **备份**：MongoDB 数据定期备份到对象存储
3. **监控**：配置简单的宕机告警（可以发到聊天里）
4. **更新**：代码更新时 git pull + pm2 restart 即可
